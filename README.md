# Target Cash Flow and Investment Capacity Model

An independent, public-data financial model evaluating how changes in Target
Corporation's sales, margins, inventory, accounts payable, capital
expenditure, and financing affect quarterly cash and modeled capacity for
additional investment. Built for an FP&A analyst preparing a recommendation
for a finance manager.

**This is an external case study — not Target's internal forecast, an
investment recommendation, or evidence of Target's adoption.** See
`docs/limitations.md` for the full scope statement.

The governing specification is `docs/Target_Cash_Flow_Final_Execution_Roadmap.docx`.
Read it before making any implementation decision that isn't already covered
by `docs/decisions.md`.

## Current status: Milestone 1 (repository setup + four-quarter data proof)

**In progress.** Repository scaffolding, schema, and validation pipeline are
built and tested. Real Target filing data has **not yet been ingested** —
see "Data acquisition" below. Forecasting, scenarios, Excel, Power BI, and
the public website are not in scope until later, gated milestones.

## Commands

Each command takes an explicit `--config` path, prints a machine-readable
JSON summary, and returns a nonzero exit status when a required gate fails.

```bash
# Register a filing source file (manually downloaded, since this environment
# has no SEC network access — see "Data acquisition" below).
target-cash fetch --config config/model.yml --mode manual --descriptor <path-to-descriptor.json>

# Report normalization state: cached filings, raw facts, derived quarters,
# and which config/metrics.csv mappings still need review.
target-cash normalize --config config/model.yml

# Run the reconciliation / lineage validation gate (the "first data gate").
target-cash validate --config config/model.yml
```

`forecast`, `backtest`, `export-excel`, `export-reporting`, and `run-all` are
not implemented yet — they are added progressively as later milestones are
authorized.

## Data acquisition

This project's fetch layer (`src/target_cash/fetch.py`, `filings.py`) is a
real SEC EDGAR client. In the current execution environment, however,
`data.sec.gov` and `www.sec.gov` are blocked by network policy, so Milestone 1
uses **manual file ingestion**: the project owner downloads specific SEC URLs
and uploads them; `target-cash fetch --mode manual` registers them with the
same hash/provenance recording an HTTP fetch would produce. See
`docs/decisions.md` and `docs/limitations.md`.

No financial figure in this repository is fabricated or estimated to fill a
data gap — a missing value is recorded as missing, and the affected
calculation fails visibly (see `docs/accounting_policies.md`).

## Definitions and data classes

- **Reported facts**: values taken directly from an SEC filing.
- **Derived historical values**: values computed from reported facts using a
  documented, deterministic operation (e.g. Q2 = 6-month YTD − Q1), with full
  lineage back to their inputs.
- **Forecasts**: projected future values. Not implemented yet.
- **Illustrative assumptions**: scenario driver values used for sensitivity
  analysis, not company guidance. Not implemented yet.

These categories are never blurred in any output.
